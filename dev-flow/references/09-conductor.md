# 09 路由编排层（跨会话派工协议正本）

## 这是什么

把「一个路由会话 + N 个工人会话」的跑批拓扑固化为协议：怎么派工、怎么回传、怎么记账、上下文超限怎么交接。对应 04-implement 的**形态 B**——04 管**节点级**归属（谁实现/谁评审/谁收账），本册管**线间级**协议（派工令/回传报告/调度台账/上下文治理），两册叠加使用，术语映射：本册「路由」= 04「调度会话」。

本册为路由编排协议正本，覆盖派工令、回传报告、调度台账、上下文治理、看门狗与两级过滤；04 管节点级归属，本册管线间协议，两册叠加使用。

## 何时用路由编排

- 宿主**有**会话工具（CreateSession / SendToSession / ReadSession / RenameSession；SendToSession 仅作路由→工人命令/提醒，不作工人回传，见 §3），且 4–6 段（实现/完成评审/验收）有一批可并行的工单 → 路由编排。
- 宿主**没有**会话工具 → 单会话 SDD（04 形态 A），本册降级规则见 §8。
- **1–3 段（需求/设计/工单）**：未配置 `models.early` 时（含无 `models` 块的旧项目）路由与用户直接对齐——这三段有决策、要来回确认；项目 `.dev-flow.json` 存在 `models.early` 时，**设计/工单**可派**前期工人**执行；**需求阶段用户在环**——小需求路由内 grilling，大需求可派**用户直连前期工人**（用户在会话内直接对，路由只派发/监控/收账，不被阻塞；工人不得替用户拍板），路由只做转发消息/派活/监控，模型取 `models.early`。
- **1–3 段参与矩阵（2026-11-20 用户裁决）**：需求 = 用户在环持续对齐（`dev-flow-grill-with-docs`，L 档强制；路由内或用户直连前期工人）；设计 = `writing-plans` + `plan-review` 出稿，用户最后签一次字；工单 = `dev-flow-to-tickets` + 3 路审核 + 裁判 + `issue-audit`，用户不参与、可抽查。**前期工人 brief 必须点名阶段技能；未点名不得派。**

## 1. 三层角色

| 角色 | 载体 | 模型 | 做什么 | 不做什么 |
| --- | --- | --- | --- | --- |
| 路由（主会话） | 会话 | 按 `models.router` 取模（机器本地 `~/.dev-flow/models.json` 逐槽位优先于项目 `.dev-flow.json`，下同）；配置了 `models.early` 时设计/工单派前期工人；需求可路由内 grilling 或派用户直连前期工人（见参与矩阵），路由只派发/转发/监控 | 与用户对齐需求（持续 grilling）/设计签字/工单抽查；生成派工令；收报告、记台账、判收账；超阈值交接 | **禁读代码定方案**；不亲自改码；不参与工人内部实现 |
| 前期工人 | 会话（CreateSession，仅当配置了 `models.early`） | `models.early` | 执行设计/工单拆分；需求可做用户直连 grilling（用户在会话内直接对）或草稿/问题清单；结果回路由与用户对齐 | 不越过 1–3 段地盘；不代替用户拍板 |
| 工人 | 会话（CreateSession） | 派工令指定：取 `models.worker.default`（机械活取 `worker.light`，未配置回退 default）；对应槽位未配置 → 停下问用户，不静默用默认 | 一票一会话一目录；按工单实施；内部按风险档派评审子代理（高风险 ≥2；M 档 1 路 + 机器门禁；S 档自检）；完成后回传 | 不向用户直接发问（疑问回传 `NEED-DECISION`）；不改共享文件；不越文件地盘 |
| 子代理 | Agent（会话内） | 由 agent 定义固定（不可选） | 一次性只读活：调研/核查/单文件评审/验证 | 不做长跑、不改仓库、不进会话列表 |

**子代理使用判据**（拿不准时用户裁决）：有决策、要来回对齐（需求/设计/工单拆分）→ 未配 `early` 时留在路由对话，配了 `early` 则可派前期工人（需求阶段可由用户直连）；一次性、只读、不下决策（调研/核查/评审）→ 子代理；要动手改、要长跑、要指定模型、要人接管 → 会话工人。

**用户直连例外**：仅「用户直连前期工人」（需求/设计要求）允许在会话内直接向用户提问，不把每个问题回传路由；实现/评审工人仍不直接问用户，疑问回传 `NEED-DECISION`。用户直连工人只回传最终产物；上下文将满先 checkpoint 到文档再交接。

**运行期取模（派工前必查）**：派工前按「机器本地 > 项目 > 未配置」逐槽位取对应槽位——机器本地 `~/.dev-flow/models.json`（形状同项目 models 块，不进仓库）逐槽位优先于项目 `.dev-flow.json` 的 `models`，损坏/形状非法时显式标出不静默回退（来源四态与 schema 见 `references/10-project-profile.md`）——取模顺序：前期工人 `early`、工人 `worker.default`/`worker.light`、工单三路/裁判 `ticketReview`/`ticketJudge`、检查员 `inspector`、完成评审/裁判 `finalReview`/`finalJudge`、闲时 `offpeak`；**该槽位未配置 → 停下问用户，不静默用默认**。唯一例外：`early` 未配置不停下问——1–3 段直接退回路由直连的旧行为。`worker.light` 未配置回退 `worker.default`；`ticketReview`/`finalReview` 数组 1 项=三路同型号、3 项=逐路指定、2 项=非法（提醒补齐，不静默补默认）。

### 架构级任务的 A-B-C 角色分工（与三层角色叠加）

架构级任务（无存量可改、跨模块、不可逆）可在三层角色之上再分 A/B/C：

- **A 主设计+写工单+回验**：持续持有设计意图，从蓝本文档生成工单，不凭记忆回验；
- **B 异构模型复审**：换模型家族审 A 的设计与工单；意见分三档（必改/建议/不成立），方向性分歧上抛用户；
- **C 干净上下文执行**：只拿蒸馏后的工单与结论，不被设计协商过程污染。

有界小任务不进 A-B-C，直接做 + 门禁兜底。A 自己也会上下文腐化，设计结论必须落蓝本文档，A 可替换。

**会话命名（路由派工必做）**：CreateSession 无 name 参数（只有 project/sourceServerId/prompt/model/retryOf）——**建会话后必须立即 RenameSession**。命名格式 `主题 + 角色/批次`，≤12 字（按字符数计，含空格与英文），如「订单导出 T-09 实施」「dev-flow 批三」「评审·第一纵切」（顺序不拘，能认出即可）。禁止把标题停在提示词首句（新会话默认标题＝prompt 首句，一排会话无法辨认）。本规则适用于路由派出的**所有**会话——工人与 04 形态 B 的检查员/评审会话；`/handoff` 交接接手的新路由会话同样立即命名（如「订单导出 路由2」）。派工令模板无「会话名」字段，会话名由路由按单号现取（如 T-09 → 「订单导出 T-09 实施」），不必预存派工令。

**槽位前缀（领取槽位后立即补）**：工人 `wt:claim` 成功、槽位号已知后，会话名立即改为 `S<槽位号数字>-<主题>`（`slot-5` → `S5`，如 `S5-订单导出T-09`；仍受 ≤12 字限制，主题取短名）。与上段叠加：先按短名建会话，领槽后补 `S<N>-` 前缀，后续改名一律保留该前缀。执行者：工人会话有会话工具则自改（RenameSession）；无工具/改不动时由路由会话代改——收到 claim 回执或 `wt:status` 看到槽位后立即改，并在派工台账备注一行。配套要求：派工令写明「认领成功后第一时间回报槽位号」（供路由改名/台账登记）；工人未回传时路由以 `wt:status` 输出为准，不等回执。

## 2. 派工令（六字段）

落点：`specs/<feature>/dispatch/<ticket>.md`（路由生成，工人读它开工）。模板 `templates/dispatch-order.md`。

```
1. 单号：T-XX（对应 issues/T-XX.md 契约全文）
2. 目标与验收：可机检的完成判据（测试/门禁/清单）
3. 文件地盘：允许路径 + 禁入清单（共享文件/并行工人地盘/旧线/版本文件）+ **必填子项「关联只读检查」**——列 capability/manifest/权限配置文件（即使禁改也要列出，供评审「能力影响」行核对，见 04/05；无则写「无需变更（理由）」）。该子项属于文件地盘的必填内容，不是可选项；`check-order.mjs` 对缺失给非阻断警告（六字段语义不变）
4. 基线 + 验证命令：当前测试基线数、run-low 命令、gate:remote 用法
5. 模型 + 槽位：模型完整 ID、槽位号（禁占他人槽）；模型按 `models` 对应槽位取（机器本地 `~/.dev-flow/models.json` 逐槽位优先于项目 `.dev-flow.json`）——该槽位未配置 → 停下问用户，不静默用默认（`early` 例外：未配置则 1–3 段路由直连，不派前期工人）
6. 回传格式 + 截止：§3 报告块落 evidence 并提交（唯一通道，不走 SendToSession）+ 超时升级条件；认领成功后第一时间回报槽位号（供会话改名）
```

**机检前置**：`scripts/check-order.mjs <派工令路径>` 校验六字段齐备且非空，缺项退出码 1——**缺字段的派工令不开工**（无脚本的条款不进正式版，本协议不靠口头）；另对「文件地盘」缺「关联只读检查」子项给**非阻断警告**（提示补列 capability/manifest/权限配置文件，六字段语义不变、退出码仍 0）。

**关键裁决同时落盘**：范围扩展、接口冲突、阶段变更等重要裁决，除发会话消息外，必须同时写进工单「## 历史」/调度台账/`decision-log.md`。消息可能未被消费或随会话丢失，落盘才是执行真相。

## 3. 回传报告（evidence 唯一通道 + 报告块）

**唯一回传通道 = evidence 落盘并提交**：工人完工后把七行报告块写入 `specs/<feature>/evidence/<ticket>-report.md` **头部**（只写一次，不发进度）并提交——**不调用 `SendToSession`，不做「尽力尝试」**。`SendToSession` 只用于路由→正在运行的工人发命令/提醒/补丁，**不用于工人完工报告**；报告没落盘才算失败，不因消息发送失败记工人失职。落盘的报告块不要套代码围栏（```）——`report-ledger.mjs` 按行识别七键，围栏内行会被当示例忽略。模板 `templates/report.md`。

```
RESULT: DONE | NEED-DECISION | FAILED
TICKET: T-XX
COMMITS: <sha…>
TESTS: <n> passed（基线 <m>，零回归/回归）
EVIDENCE: <报告文件路径>
REVIEW: <n 个评审子代理>，必须修 <k> 条（处置：…）
ASK: <NEED-DECISION 时一行问题>
```

- **详版 ≤150 行**：七行块置报告文件头部，详版接在块后——只放结论/证据/命令输出，不贴大段代码，diff 用 `--stat`（对应 §5 报告/证据限长）。
- **重复投递幂等**：同一工人重写报告文件/多次投递，路由只取**最后一份完整报告块**；`report-ledger.mjs` 按提交号去重，重复只记一次 duplicate，不重复落账。
- **进度不转发**：路由不把进度转述给用户；只转 `NEED-DECISION` 与最终收账一行。
- **evidence 是正常通道（原「手递降级」转正，2026-11-20 W-04 统一改版）**：不论宿主会话工具可用与否，工人完工一律把七行报告块置 `evidence/<ticket>-report.md` **头部并提交**，不再调用 `SendToSession`、不做「尽力尝试」（历史口径留档：2026-11-20 前曾要求先发消息、失败才落 evidence——cold 会话已知 `proto.sessionNotFound`；旧派工令可能仍带该措辞，以本条为准）；收账由「报告监视器 + 路由每轮开头扫」双保险兜住（见下「报告监视器」小节）。
- **收账口径**：路由只读报告块判收账（RESULT/TESTS/REVIEW 三行定绿红），需要细节按 EVIDENCE 路径回查文件——不重新读 diff 复审（证据文件的存在性由 §9 看门狗兜底；本协议无 diff 复审环节）。03 审核通过后按 08 建环节；**收账必做项 = specs 三件套（台账/状态/追溯）+ 时记环节同步**（与三件套同批，不是可选项）：按 `state.json` 的 `taskchron` 映射（无该块时按 08 指定的 `tasks.md`/`handoff` 映射记录）定位环节——非环节最后一张收账 → `update_task` 刷新所属环节备注（已完成/总数 + 一句大白话进度，不改状态）；最后一张未收账单 → `set_task_status` 勾该环节（最后一个环节等 05/06 出口满足后再勾）；全部环节完成且最后环节出口满足后父任务收口。**新鲜度检查：最新销单时刻 > `taskchron.lastSyncedAt` 即「时记过期」，必须同步后才能收尾本轮，同步成功后写回 `lastSyncedAt`**（无时间可比不判过期）。该规则由 issue-audit 第 8 项门禁机器硬拦（**仅 `--phase final-review`＝`wt:done` 全量审计**；staged/tickets 不查）：过期直接红阻断收工，按 08 册同步后写回 `lastSyncedAt` 即转绿；`taskchron` 块/字段缺失（旧 feature）或 `taskchron.mode=off` 自动跳过，判定纯离线 git/state、不要求 MCP 可达。`taskchron` MCP 不可达时当轮声明「时记未同步」跳过，不伪写锚点，恢复后补同步。**禁止以「调度动作不入时记」为由跳过环节状态维护**——该口径只约束不建工单级条目，刷新备注/勾环节/收口是收账必做动作。归档已完成且无后续用途的工人会话（见 §12）。
- **派工简报收尾检查**（模板 `templates/dispatch-order.md` 同款）：①完工后立即把报告块落 `evidence/<ticket>-report.md` 头部并提交（唯一通道，不调 `SendToSession`）；②同批写 `evidence/<ticket>-retro.md`（先调 `dev-flow-retro`，文件头 `SKILL:` 行，模板 `templates/ticket-retro.md`）；③关键裁决可能以会话消息形式到达（路由→工人方向）——开工初期与收尾前各读一次会话消息。
- **单票 retro 收账校验**：收账时同批读 `evidence/<ticket>-retro.md`，校验文件头 `SKILL: dev-flow-retro` 行——**缺失（或未调技能硬写）＝retro 未完成**，下一轮要求工人重做；**不阻塞七行报告收账**（七键语义不变，`report-ledger.mjs` 不读 retro）。工人侧必须先调 `dev-flow-retro`（原版 `retro` 是 `disable-model-invocation: true`，工人不能自动调）；宿主只能读不能调时工人写 `SKILL: dev-flow-retro(read)` 并注明原因。retro 建议的落地走 §4「收账后三路分诊」。（`watch-reports.mjs` 只按 `.md` 识别 evidence 新文件，工人单独补做 retro 也会触发一次唤醒——路由按台账幂等跳过即可，不产生坏账。）

### 报告监视器（watch-reports.mjs）——后台盯 evidence，宿主唤醒收账

**双保险纪律（硬约束，缺一不可）**：监视器只负责**缩短延迟**，不是唯一通道——机器休眠、后台进程被杀、监视器漏跑都会断（2026-11-20 机器休眠期间监视器没跑、报告没人收即反例）。因此两条同时做：①路由把监视器挂为后台任务盯 `specs/<feature>/evidence/*.md`，新报告稳定即唤醒收账（延迟从分钟级缩到秒级）；②**路由每轮开头必须再主动扫一遍 `specs/<feature>/evidence/*.md` 兜底**——对照台账已收账行，发现未收账的报告立即收，保证最坏情况（监视器全断）下一轮内必收。

**用途与机制**：工人把七行报告块置 `evidence/<ticket>-report.md` 头部并提交后（§3 唯一回传通道），监视器启动时对 evidence 做 mtime+size 基线快照，每 interval 秒对比；发现新文件/内容变化后等稳定窗（连续 settle 秒无进一步变化，防读到半写报告），打印新报告清单退出；宿主在后台任务退出时自动唤醒路由，路由按清单收账后补挂下一轮监视器。

**用法（零依赖，Node 22+，Windows/Ubuntu，只读不写仓库、不占端口）**：

```
node scripts/watch-reports.mjs --root <项目根> --feature <feature>
                               [--interval-sec 5] [--settle-sec 15] [--timeout-min 240] [--json]
node scripts/watch-reports.mjs --self-test    # 自带自检（临时夹具跑完即删）
```

**输出契约**：触发打印 `NEW_OR_CHANGED_REPORTS=<逗号分隔文件名>`，退出码 0；`--timeout-min`（默认 240 分钟）内无报告打印 `WATCH_TIMEOUT_NO_REPORT`，退出码 0（正常返回，不是错误）；参数/读取错误退出码 1。`--json` 输出同一信息的 JSON（附 `line` 字段，宿主解析二选一）。

**路由侧动作**：被唤醒后按清单对照台账收账（只认台账未收账的报告，重复投递幂等跳过）；监视器断了不用急——每轮开头扫兜底，下一轮由路由补挂。

## 4. 调度台账（路由的外部记忆）

落点：`specs/<feature>/dispatch/LEDGER.md`，**append-only**，一行一次状态变更（一单可多行；已关闭行按月/每 20 行整段归档见 §5，归档不改写内容）。模板 `templates/ledger.md`。

```
时间 | 单号 | 状态(派发/施工/已完成/待裁决/失败) | 提交 | 报告路径 | 一行摘要
```

路由上下文只保留：**最后一行台账 + 未决问题清单**。任何历史细节一律按台账/报告路径回查，不驻留窗口。

**报告→台账自动化（批二）**：`scripts/report-ledger.mjs --ledger <台账> --report <报告块文件>`——校验七行必填（RESULT 枚举合法；NEED-DECISION 时 ASK 必填一行问题）、按提交号去重（须含 a–f 字符防纯数字误杀、长短前缀互认；无提交号退化为单号精确匹配；重复投递只记一次 duplicate，幂等不重复落账）、追加一行（状态映射 DONE→已完成 / NEED-DECISION→待裁决 / FAILED→失败，插在表块末尾、后文之前；单元格管道符转义、摘要列缺位或撞列不写不覆盖报告列）；失败给缺项清单（exit 1）。不改变 append-only 纪律（去重范围见 §5 归档边界），未决问题清单仍由路由手工维护。

**收账后三路分诊（单票 retro 落地）**：路由收账时读 `evidence/<ticket>-retro.md` 的三分类建议，按路落账，并登记每功能一张的分诊表 `specs/<feature>/retro-triage.md`（模板 `templates/retro-triage.md`；表：单号/retro/项目级/dev-flow 级/经验卡/状态）：

| 分诊 | 去向 | 边界 |
| --- | --- | --- |
| 项目级 | 项目 docs / 台账 / 工单模板 / 测试 / 门禁 | 改项目规则须问用户批准，不静默改 |
| dev-flow 级 | 追加 `docs/issues/retro-candidates.md`（append-only 候选收件箱），dev-flow 维护路由评估后开 W 单并在本仓实现 | 其他项目的路由**不直接改 dev-flow 仓**，只报候选 + 证据 |
| 通用经验卡候选 | 按项目配置查经验卡索引：`.dev-flow.json` 的 `experience.index`（解析落地前视为未配置）或项目 AGENTS/文档指针；**技能不写死「开发随记」或任何具体知识库路径** | 未配置或 `experience.mode=off` → **跳过共享卡分诊**（正常路径，不报错、不阻塞收账），候选只写项目级 `docs/dev-guide/experience.md`；已配置：先查重；跨项目两次独立命中升共享卡（派生副本不算独立项目）；纪律/红线类例外可直接进共享卡组；真用上才写 `卡:卡名` |

路由每轮四块的「下一步」可带一行「本单 retro 分诊：项目 X / dev-flow W-XX / 经验卡 Y」；分诊表随批次综合评审一起看。

**复盘审阅 checkpoint（retro digest，2026-11-20 用户裁决）**：每批收口（本批最后一张工单收账后）与每次公开发布前，路由必产出 `specs/<feature>/dispatch/retro-digest.md`（模板 `templates/review-digest.md`；每批覆盖更新——当前批快照，历史按台账/提交回查），三节：①**自审清单**——已自审通过、每条附理由/证据，自审边界只有四类（项目级经验记录；候选收件箱登记；有测试/自检覆盖且不改门禁语义的 dev-flow 变更；经验卡首次命中）；②**待用户拍板清单**——只列把握不了的，升级条件＝改门禁/协议核心语义、公开发布、共享卡升级、不可逆/安全敏感、或自审没把握；③**未决**——写明去向。**不得堆积**：未产出 digest 不得开下一批；digest 不允许有跨批未处理的 pending 项。

## 5. 路由上下文与成本治理

**上下文阈值（超限交接）**

- **阈值**：接近 smart zone（约 150k tokens）或到达上下文边界（换批/换阶段）时触发。
- **动作**：`/handoff` 写交接文件（台账路径 + 未决清单 + 下一批候选）→ 新路由会话接手（先读台账恢复现场）→ 旧路由归档。会话可丢，状态在台账。
- **禁止**：超阈值硬撑——降智运行是最大浪费（dsh 与 ask-matt 同口径）。

**成本纪律（实现阶段默认值，批量跑批适用）**

- **一票一会话 + 上下文边界清空**：实现阶段每张工单结束即上下文边界（不是 `state.stage` 阶段切换）——默认 `/clear` 或新开会话，新会话只读工单 + ≤10 行 handoff 摘要恢复；不要一条会话硬扛多单，需要搬运上下文用 `/handoff`；**禁止 Continue 硬撑到 smart zone（约 150k）**。
- **派工令指针化**：简报全文落 `specs/<feature>/dispatch/<ticket>.md`；CreateSession 的 prompt 只放该路径 + 与本批差异项（≤500 字），不重复贴全文——全文进 prompt 等于双倍上下文成本。
- **报告/证据限长**：报告块七行不变；详版报告 ≤150 行，只放结论/证据/命令输出，不贴大段代码，diff 用 `--stat`；单票跑工单定义的定向验证命令（命令本身是全量则照跑），全量套件批末跑一次。
- **台账/状态瘦身**：已关闭台账行按月（或每 20 行）整段转入 `LEDGER-archive-YYYY-MM.md`（内容不改写，属 append-only 的归档例外），`LEDGER.md` 正文只留最近一段未归档行 + 未决问题清单（已决项并入对应单摘要）；`state.json.history` 只留最近 10 条，旧条目转 `state-history.json`（读 `history` 的脚本只看当前 10 条，归档仅作历史回查）；路由每轮只读台账尾部（最后一行 + 未决清单）。
- **归档边界**：归档单视为已收口——`report-ledger.mjs` 的幂等去重与 `watchdog.mjs` 的巡检**仅覆盖当前 `LEDGER.md`**；归档文件不再接收报告、不再巡检（需要覆盖归档须扩展脚本，另单处理）。

## 9. 看门狗（外部巡检，只报不修）

落点 `scripts/watchdog.mjs`（零依赖 Node）。照 dsh 原型实证（HealthBoard + `status` 退出码表）取其已实现部分；语义看门狗（死循环/drift/工人是否真推进）与投机执行**不做**（dsh 同样未实现）。

**健康项模型**：每个部件一个健康项，一项只有一个写入者＝看门狗自身（只读仓库事实，只写自己的状态文件，不与他人互写）：

- `lease` 租约——租约在但超过阈值无提交（默认 24h，`--lease-stale-hours N` 可调；工作树提交查不到时按租约 `started` 兜底并在明细注明；租约 `info.json` 不可解析同样计入本项失败）；
- `ledger` 台账——已收账/已完成行的报告列为空或占位（＝项目收工门禁后报告缺失）；台账文件存在但无 时间/单号/状态 表视作**未启用**（记 note 不计失败，不误报部件错）；表缺「报告」列则该表行跳过（不假定列位）；
- `gate` 门禁——已收账行报告列中的证据路径指向的文件不存在（相对 feature 目录或仓库根解析；token 识别口径：含 `/` 或 `\` 且以 md/json/txt/log/csv/html 结尾，裸文件名不检）；`--gate-file` 可喂退出码文件（每行 `名字 码` 或 JSON 对象），非零即红、文件不可解析计入本项失败。

**三振与自清**：同项连续失败 **3 次才报错**（exit 2）；下一次成功即自清清零；**同一问题报过一次不再重复告知**（明细仍逐巡可见，建议行只在首报出现）。

**退出码四档**：`0` 正常（含 1–2 次失败未满三振——正常静默）；`1` 没跑或运行时错（参数/路径/内部异常）；`2` 部件错（三振成立，**重启无用，只报不修**）；`3` 等配置（既无在盯租约也无台账，重启无用，先 setup）。

**边界（写死防越界）**：

- 会话是否活着脚本查不到——留给会话侧 `ReadSession`；看门狗只查文件面事实（租约/台账/门禁产物）。巡检范围仅当前 `LEDGER.md`；已归档行不再巡检（归档视为已收口，见 §5）。
- **禁止**自动重启 / 杀进程 / 改任何租约。动作只有两档：输出建议——nudge 工人（`SendToSession` 询问，先 ReadSession 确认会话活性）或升级用户。
- **尊重人工停机**：`<槽位根>/STOP`＝全局停机（整体静默不介入，三振计数不动）；`<槽位根>/<N>/HOLD`＝该槽位人工暂停（跳过其租约检查）。
- 巡检可独立会话或用户手动触发；**不装 cron**。三振计数存 `--state` 状态文件（默认系统临时目录 `devflow-watchdog-<root哈希>.json`，不落仓库、不进 git status）。

```
node scripts/watchdog.mjs --root <仓库> [--ledger <台账>] [--slots-dir <.slots目录>]
                          [--lease-stale-hours N] [--gate-file <退出码文件>] [--state <状态文件>] [--json]
node scripts/watchdog.mjs --self-test
```

槽位根定位：`--slots-dir` 显式 > `.dev-flow.json` 的 `slots.dir` > `<root>/../<名>-trees/.slots`（项目约定）> `<root>/.slots`。

## 10. 两级过滤（Trigger）

Source（工人回传/门禁结果/CI 产出）→ **Gate（程序判定，零模型）** → 模型（仅歧义进语义判断）：

- Gate 三件机检：`check-order.mjs`（派工令六字段，§2）、`report-ledger.mjs`（报告块七行校验+去重落账，§4）、`watchdog.mjs`（巡检退出码红绿，§9）。
- **只有两种东西进路由（模型）判断**：`RESULT: NEED-DECISION` 与门禁红（watchdog exit 2 / 门禁退出码非零）。其余 DONE 且门禁绿 → 直接落台账收账，路由不重读 diff 复审。
- **幂等**：同一报告块（提交号/单号重复）重复投递只记一次 duplicate，不重复落账（对应 dsh intake 幂等）。

## 11. 每轮汇报四块（路由 → 用户，含简短确认）

**每一轮**回复用户（含一句话确认、状态回复、收账）都必须输出这四块；单会话形态（04 形态 A/C）首块标题写「🚧 本会话正在干的活」，至少用前三块，第四块批量落地时补。每块没有内容就写「无」，不许省略标题。**视觉分隔（硬规则）**：每块用 Markdown 三级标题独立成行（`### <emoji> <块名>`），**块与块之间至少空一行，禁止四块紧贴堆成四行**——四块要在视觉上真正分开（W-03）。

1. **🚧 本路由正在干的活**：只列**当前已派出去、正在施工**的工单/会话/模型/截止；已完成、待派的不写；没有写「无」。细节按台账/报告路径回查，不转发工人进度。
2. **👉 需要你拍板或动手的事**：没有写「无」。只有「用户不能自己做主」或「必须在宿主面板操作」的才进清单；会话插话写成「停掉某会话——原因」。**未处理前每轮重复**；处理后清掉对应条目。
3. **📋 下一步可以开的任务**：按依赖/优先级列，注明前置是否满足（台账/门禁/工单状态）；没有写「无」。
4. **🔍 阶段性综合评审触发点**：已做几批、下一批由哪几张落地单触发、之后怎么分批（按 05 的分批综合评审口径）；未到触发点写「无」。

最小模板（完整示例见 `templates/router-round.md`）：

```
### 🚧 本路由正在干的活
<当前已派出去、正在施工的工单/会话/模型/截止；无写「无」>

### 👉 需要你拍板或动手的事
<具体动作/命令；无写「无」>

### 📋 下一步可以开的任务
<任务 + 前置是否满足；无写「无」>

### 🔍 阶段性综合评审触发点
<已做几批 / 下一批触发条件；无写「无」>
```

> 汇报只给这四块，不转发工人进度；细节按台账/报告路径回查。发送前可跑 `node scripts/check-round.mjs <回复文件>` 自检四块是否齐全（自检工具，不强制钩子；单会话首块写「本会话正在干的活」机检同放行）。机检只校验四个块名齐备，**不强制标题级别与空行**——「### 标题 + 块间空行」的空行分隔靠本节与 `templates/router-round.md` 规范约束；自检与维护者测试样例固定用该标准格式，防文档回退（W-03）。

## 12. 宿主工具行为备忘（会话/闲时/归档）

- **SendToSession 排队**（仅路由→工人命令/提醒，不作工人回传，见 §3）：对 busy 目标只排队，没有优先级参数；不能靠它插队或紧急停止。
- **InterruptSession 需要 executionId**：`ListSessions` 常不返回 executionId；需要立即停止时，唯一可靠手段是宿主面板的「停止会话」。
- **闲时任务挂载**：OffPeak/闲时任务在「发起它的会话」内执行。必须新开工人会话，并在该工人会话里挂载；禁止在调度/路由会话里直接挂（否则调度会话自己写码 + 污染上下文）。模型字段按宿主要求用裸名；可按 `models.offpeak` 取（机器本地 `~/.dev-flow/models.json` 优先于项目；未配置 → 停下问用户，不静默用默认）。
- **归档不等于停止**：`SetSessionArchived` 只归档元数据，不中断执行。作废会话必须先终止执行，再归档；归档后核对槽位租约与工作树，确认执行已停。
- **完成且无后续用途的会话及时归档（用户 2026-11-20 裁决）**：工人/检查员/评审/裁判会话在报告落盘收账、确认无待处理消息、无待复评/返工、无槽位租约后，由路由立即 `SetSessionArchived` 归档；待复评会话保留到复评完成再归档。归档≠停止执行：作废会话必须先终止执行再归档，归档后核对槽位租约与工作树。

# 11 测试体系

> 本册是测试的唯一体系说明：按改动类型决定测什么、两级门禁怎么跑、证据怎么留、抖动与断言怎么治理。项目差异走 `.dev-flow.json` 的参数槽；本册不写具体项目命令。

## 1. 六条核心原则

1. **测试即需求**：测试描述的是可观察行为，不是实现细节。
2. **先失败后通过**：修 Bug 先写复现测试，看它红；新功能先写失败测试，再写最小实现。
3. **改哪测哪**：只跑本次改动相关的测试与检查；全量留给交付/发布门禁。
4. **全绿才交付**：当前级别门禁任何一项失败，不得交付，修完再汇报。
5. **测试要稳定**：禁随机失败、禁真实网络、mock 时间与随机数；不确定的测试等于没有测试。
6. **分层不重复**：单元测行为、集成测接线、E2E 测用户路径；同一事实不在三层重复断言。

## 2. 按改动类型查表

| 改动类型 | 最低测试要求 |
| --- | --- |
| 修 Bug | 先写复现测试，修复后转绿 |
| 业务逻辑（utils / services / stores / lib） | 新增或更新单元测试 |
| UI 组件 | 组件测试；关键路径加 E2E |
| 算法 / 转换层 | 对应层单测（Rust `#[cfg(test)]`、Python `tests/` 等） |
| 数据 / 协议 / 迁移 | 契约测试 + 迁移测试 + 双端同步测试 |
| 重构 / 重命名 | 原测试全绿，必要时迁移测试 |
| 纯文案 / 样式 | 可豁免，交付说明写明理由 |
| 一次性脚本 / 依赖真实硬件或外部付费服务 | 可暂不写，登记未测试区或说明 |

## 3. 两级门禁

- **快门禁（日常提交）**：lint / format / 类型检查 / 本次改动文件的定向测试。**不跑构建、不跑全量、不跑 E2E**——构建脚本常改写工作区，全量套件会拖垮桌面。
- **慢门禁（交付 / 推送 / 发布）**：全量测试 + build + E2E + 农场腿；在 133（Windows）/ 144（Linux 容器）农场跑，本地只做秒级预检。
- **按改动类型分流**：文档/资产放行；前端只跑前端段；Rust 只跑 Rust 段；Python 只跑对应包；插件只跑插件套件；无法归类走全量兜底。
- **项目参数**：测试命令、门禁命令、农场目标写项目 `.dev-flow.json` 或项目 AGENTS，不写进本册。
- **边界**：项目要求「每次修改即提交」时，两级门禁退化为一级——此时快门禁必须按改动类型分流，否则每次提交都是全量，门禁会因太慢被 `--no-verify` 绕过。

## 4. 未测试区

项目维护 `docs/untested-areas.md` 或等价物：改到即补、补完即删、清单只减不增。任何门禁项失败不得交付。

## 5. 并排考卷

存在多条并存实现路径时（新旧逻辑并行、两套算法对照），必须配可机械对照的对照测试：同一输入两条路径各跑一遍，输出一致才算绿——防止「并存」悄悄变「漂移」。

## 6. 抖动治理（全量套件）

全量测试「每轮红一批、失败文件随机轮换、单文件隔离跑必绿」时，按序三步：

1. **升测试框架大版本**：新版的环境销毁/进程池处理更稳；跳更高版本前先查 `engines` 与周边（Node/Vite）要求，超回滚线就止步当前大版本。
2. **清局部超时覆盖**：全库 grep `setConfig({ testTimeout` 与逐用例显式超时参数——模板化生成的测试常把全局放宽的超时又压回去，是「红轮文件轮换」的常见真凶。
3. **销毁竞态降噪**：jsdom/antd 类库的定时器与 rAF 在环境销毁后触发属库内部竞态；用框架官方标记精确豁免（如 vitest 的 `VITEST_AFTER_ENV_TEARDOWN`），只吞带标记的。**严禁** `dangerouslyIgnoreUnhandledErrors` 全量掩码和 `isolate:false` 关隔离。

验收：连跑 10 轮全绿（机器疲劳会放大抖动，验收前让机器凉透）。确定性失败是真 bug，不走本流程。

## 7. 断言质量

文本存在性断言只锚**只增不删的终态物**：

- 安全锚：结构性存在（章节标题/工单号/函数名/导出符号）、常量字面量、单向终态词（如「✅ 已兑现」）。
- 危险锚：会翻转的过程态（⬜/计划中/进行中）、会被格式化工具重排的松散文本。
- 写锚三问：这个字面量六个月后还在吗？谁会在什么场景改它？改它的人会不会想到同步改断言？三问有一个答不稳，换锚。
- 被迫改锚：在断言 desc 里注明变更依据与日期，留给抽查者分辨「断言腐化」与「事实演进」。

## 8. 证据格式

每个节点/交付必须留：**命令 + 退出码 + 关键输出（尾部/红行）+ 产物路径（日志/截图/报告）**。「我检查过了」不算证据。

农场门禁：报告 `run_id`、目标腿（133/144）、退出码；完整日志留目标机，摘要回传。

## 9. 评审衔接

- **工单级**：按 `04-implement.md` 的风险分档——高风险 ≥2 评审子代理交叉、M 档 1 路 + 机器门禁、S 档自检。
- **功能级**：`05-final-review.md` 的 3 路 + 裁判，不因风险档降级。
- **默认异构，项目配置可同型号**：同一模型开两个对话互审，训练数据/偏好/盲区高度相关，审得出笔误、审不出系统性盲点——3 路默认换模型家族。项目 `.dev-flow.json` 的 `models.ticketReview`/`models.finalReview` 显式指定同型号时以配置为准，并在报告校准记录声明；裁判按 `models.ticketJudge`/`models.finalJudge` 配置取；对应槽位未配置 → 停下问用户，不静默用默认。既未配置异构、又做不到多模型时必须在报告里声明并加倍人工抽查。
- **分歧处理**：意见分三档（必改/建议/不成立），判「不成立」必须写理由；方向性分歧上抛用户；两三轮封顶，超过说明是方向性问题。

## 10. 常见错误

| 错误 | 后果 | 纠正 |
| --- | --- | --- |
| 先写实现再补测试 | 测试证明不了行为 | 先红后绿 |
| 测试 mock 内部协作者 | 重构就红 | 只 mock 系统边界 |
| 只跑单测不跑集成 | 没接线/跑不通 | 节点检查加接线清单 |
| 用全量测试当日常门禁 | CPU 风暴、被 `--no-verify` 绕过 | 快门禁按改动类型分流 |
| 断言锚过程态/松散文本 | 事实演进即红 | 只锚终态物与常量 |
| 三路评审用同一模型且无项目配置背书 | 盲区相关，剧场式通过 | 换模型家族 + 裁判按 `models.*Judge` 配置取；确需同型号走 `models.*Review` 配置并在校准记录声明 |

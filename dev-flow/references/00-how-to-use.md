# dev-flow 怎么用（第一次先读这个）

## 0. 你只需要记住一句话

**任何时候不知道下一步，就调用 `dev-flow`。** 它会读状态、告诉你现在在哪、下一步做什么、用哪个技能、产出什么、怎么验收。

你不需要记 Matt 的流程，也不需要记 Superpowers 的流程；你只需要按它说的下一步做。

---

## 1. 一个完整例子：图层右键导出 DXF

假设你要给一个 GIS 桌面项目加「图层右键导出 DXF」。下面是 dev-flow 会带你走的六步；路径和命令都是示例，实际以项目 `.dev-flow.json` 为准。

### 第 1 步：开始（你调用 dev-flow）

你说：

> 用 dev-flow 开一个新功能：图层右键导出 DXF。

dev-flow 会做：

1. 在 `specs/dxf-export/state.json` 建状态；
2. 问你一个问题：这次大概多大？单文件小改（S）/ 单模块（M）/ 跨模块或改协议（L）？
3. 你说 M。
4. 它输出：

```
【dev-flow】
功能：dxf-export（图层右键导出 DXF）
档位：M
现在：需求
上次：初始化
下一步：和 AI 聊清楚「谁在用、解决什么问题、什么算成功」
需要你做：说出你的真实需求和使用场景
可以调用：brainstorming
产出：specs/dxf-export/spec.md
门禁：无独立闸门（并入设计审）
状态文件：specs/dxf-export/state.json
```

### 第 2 步：需求（AI 陪你聊，产出 spec.md）

你调用 `brainstorming`（dev-flow 会提示），AI 会一次问一个问题：

- 谁用这个功能？在什么场景下用？
- 现在没有这个功能时，他们怎么干活？
- 导出 DXF 时，哪些图层/要素要带上？坐标系怎么处理？
- 什么算成功？导出的文件能被 CAD 打开、图层名不乱码、坐标正确？
- 明确不做什么？（比如不做批量导出、不做样式映射）

聊完，AI 写 `spec.md`：

```md
# 图层右键导出 DXF

## 为什么做 / 成功指标 / 非目标
- 为什么做：测绘用户需要把当前图层交给 CAD 同事，现在只能整图导出或手工转格式。
- 成功指标：1 万要素内 5 秒导出完成；中文图层名零乱码；用户 3 步内完成导出。
- 非目标：不做批量图层导出、不做符号/样式映射、不改现有整图导出。

## 目标
图层右键菜单增加「导出 DXF」，导出当前图层的可见要素。

## 非目标
- 不做批量图层导出
- 不做符号/样式映射
- 不改现有整图导出

## 用户故事
1. 作为测绘用户，我希望在图层右键直接导出 DXF，这样不用先导出整图再裁剪。
2. 作为 CAD 同事，我希望导出的 DXF 图层名不乱码，这样能直接打开使用。

## 验收标准（EARS）
- AC-1 WHEN 用户在图层右键选择「导出 DXF」 THE SYSTEM SHALL 弹出保存对话框并导出当前图层可见要素。
- AC-2 WHEN 图层名含中文 THE SYSTEM SHALL 保持中文名不乱码。
- AC-3 WHEN 当前图层没有可见要素 THE SYSTEM SHALL 提示「没有可导出的要素」且不生成空文件。
- AC-4 IF 导出过程中写文件失败 THEN THE SYSTEM SHALL 提示错误并保留原文件不变。

## 非功能需求
- 1 万个要素以内，导出在 5 秒内完成。
- 不阻塞主线程超过 200ms。
- 导出文件坐标与当前地图坐标系一致。
```

### 第 3 步：设计（AI 写，**你审**）

dev-flow 切到设计阶段，提示 AI 用 `writing-plans` + `plan-review` 的工艺写 `design.md`。设计文档至少包含：

- 接口：右键菜单怎么注册、导出命令走 IPC 还是前端、文件怎么写；
- 数据流：图层 → 要素 → DXF 写盘；
- 失败模式：空图层、写盘失败、中文编码、坐标系不一致；
- 备选方案：前端写 vs Rust 写，为什么选后者/前者；
- 回滚：出问题怎么撤掉入口；
- 非功能怎么验证。

写完后 dev-flow 输出：

```
现在：设计
下一步：你审 design.md，确认接口和失败模式
需要你做：读 design.md，回复「设计通过」或指出要改的地方
可以调用：plan-review（可选，让 AI 先自检）
产出：specs/dxf-export/design.md
门禁：等你签字
```

**这是整个流程唯一一次实现前的人工签字。** 你不需要审工单细节，但设计要审。

### 第 4 步：工单 + 3 路审核（你不参与）

你回复「设计通过」后，dev-flow 记录 `designApproved=true`，进入工单阶段：

1. 用 `dev-flow-to-tickets` 拆成纵切工单（`issues/T-01.md` 一张一个文件），每张写：交付、Blocked by、改哪个文件、验证命令、回指哪条 AC。
2. 同时启动 3 个审核 agent：
   - 设计符合性：工单有没有覆盖设计里的每条要求，有没有夹带设计外的东西；
   - 拆解正确性：粒度、依赖边、文件范围、预重构顺序；
   - 可验收性：每张工单有没有可执行判据，测试能不能证明行为。
3. 裁判合并去重，只留「必须修」。有必须修就回工单重拆；没有就通过。

dev-flow 输出：

```
现在：工单
上次：设计已签字
下一步：工单 3 路审核已通过，准备开工
需要你做：无
可以调用：subagent-driven-development
产出：specs/dxf-export/tasks.md
门禁：通过（3 路无必须修）
```

### 第 5 步：实现 + 节点对标

开工后，每个节点（一张工单/一个可验证切片）完成时，dev-flow 会要求：

- 跑该工单的验证命令，保存输出到 `evidence/`；
- 节点检查员只拿「工单 + 设计 + diff + 测试输出」，逐条对：
  - 工单要求做了没有；
  - 设计接口有没有被绕过；
  - 有没有降级实现、假接线、顺手重构；
  - 测试是不是真的证明了行为；
  - 有没有接线遗漏（入口、IPC 单源宏注册、UI、资源清单）；
  - 有没有回归风险。
- 偏离就停：回实现或回工单，不往下滚。

### 第 6 步：完成后 3 路评审（你不参与）

所有工单完成后，dev-flow 启动 3 路评审：

- 设计符合性：每条 AC 是否有证据，有没有少做/多做；
- 正确性/架构：边界、错误处理、依赖方向、性能；
- 测试与回归：正常/边界/异常、旧功能有没有被破坏。

裁判合并，只留「必须修」。修完再审一轮，连续两轮无新增必须修才算稳定。

### 第 7 步：交付 + 你实机验收

通过后，AI 写 `acceptance.md`：

```md
# 验收：图层右键导出 DXF

## Summary
图层右键菜单新增「导出 DXF」；导出当前图层可见要素。

## Evidence
Before: 只能整图导出后手工裁剪。
After: 右键单图层直出 DXF（见测试输出 evidence/AC-1.txt）。

## Merge Danger
Door: two-way
Blast Radius: 图层右键菜单；不影响整图导出。

## 怎么验
1. 打开一个有中文图层名的工程。
2. 图层右键 →「导出 DXF」→ 保存到桌面。
3. 用 CAD 打开导出的文件。
4. 预期：图层名中文正常；要素数量与当前可见要素一致；坐标位置正确。

## 已知限制
- 只导出当前图层；批量导出不在本期。

## 失败时请发回
- 操作步骤、截图、`~/<项目>/logs/` 下当天的日志。
```

你验收通过 → 流程结束。
你验收不通过 → 进入复盘：哪个环节漏了？需求没写清？设计没覆盖？工单没审出来？实现跑偏？评审没抓到？然后把「漏」变成一个新增检查/模板字段/评审维度，再重跑受影响阶段。

## 2. 中途接手：换会话怎么继续

新会话里你说：

> 用 dev-flow 继续 dxf-export。

dev-flow 会：

1. 读 `specs/dxf-export/state.json`；
2. 运行 `flow-status.mjs`，检查产物是否存在、门禁是否通过；
3. 告诉你现在在哪、下一步是什么；
4. 如果证据不完整，重跑当前步骤；如果状态损坏，从 `handoff.md` 和最近提交重建。

你不需要重新讲一遍需求。

---

## 3. 你只需要记三个动作

1. **开始**：`用 dev-flow 开一个新功能：<一句话>`
2. **继续**：`用 dev-flow 继续 <功能名>`
3. **卡住**：`用 dev-flow 看看我现在该干嘛`

其他都由它路由。

---

## 4. 什么时候不用 dev-flow

- 纯查询、纯讨论、没有落盘产物：不用。
- 单行文案/样式微调：可以直接改，改完补一句验收说明；或者用 S 档走一遍。
- 真正的紧急线上故障：先用 `diagnosing-bugs` 止血，事后补流程。

---

## 5. 常见错误

| 错误 | 后果 | dev-flow 怎么拦 |
| --- | --- | --- |
| 需求没聊清就写设计 | 设计得再漂亮也可能做错东西 | 设计阶段要求 spec.md 有目标/非目标/AC |
| 设计没签字就开工 | 实现跑偏没人拍板 | `designApproved` 门禁 |
| 工单只写「实现 X 功能」 | 实现者靠猜 | 工单模板要求文件+验证命令+AC 回指 |
| 实现时顺手改设计 | 设计和代码对不上 | 节点对标 + 变更控制 |
| 评审只跑一个 agent | 自己批自己 | 3 路 + 裁判 + 不同模型 |
| 验收只靠「我觉得行」 | 问题漏到用户 | 验收模板要求步骤+预期+失败回传 |
| 验收失败不复盘 | 同类问题反复发生 | 复盘模板 + 流程升级 |

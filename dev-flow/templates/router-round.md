# 每轮汇报四块模板（路由 → 用户）

> **每一轮**用户可见回复（含一句话确认/状态回复/收账）都必须带这四块，没有内容写「无」，不许省略标题。
> 每块用 `### <emoji> <块名>` 三级标题独立成行，**块与块之间至少空一行，禁止四块紧贴堆成四行**——四块要在视觉上真正分开（09 §11，W-03）。
> 单会话形态（04 形态 A/C）首块写「🚧 本会话正在干的活」，至少用前三块；第四块批量落地时补。
> 发送前自检：`node <技能目录>/scripts/check-round.mjs <回复文件>`（退出码 0=四块齐全；机检只校验块名，不强制标题级别与空行）。

```
### 🚧 本路由正在干的活
<当前已派出去、正在施工的工单/会话/模型/截止；无写「无」>

### 👉 需要你拍板或动手的事
<具体动作/命令；无写「无」>

### 📋 下一步可以开的任务
<任务 + 前置是否满足；无写「无」>

### 🔍 阶段性综合评审触发点
<已做几批 / 下一批触发条件；无写「无」>
```

规则回顾（详见 `references/09-conductor.md` §11）：

- 每块标题独立成行、块间至少空一行；**禁止四行紧贴**（机检不拦紧贴，靠本模板约束，别拿机检放行当免死金牌）。
- 第一块只列**当前已派出去、正在施工**的工单/会话/模型/截止；已完成、待派的不写；没有写「无」。
- 第二块只收「用户不能自己做主」或「必须在宿主面板操作」的事；会话插话写成「停掉某会话——原因」；**未处理前每轮重复**，处理后清掉。
- 第三块按依赖/优先级列，注明前置是否满足（台账/门禁/工单状态）。
- 第四块写已做几批、下一批由哪几张落地单触发、之后怎么分批（按 05 的分批综合评审口径）。
- 汇报只给这四块，不转发工人进度；细节按台账/报告路径回查。
